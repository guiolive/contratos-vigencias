Como capturar os dados

Tudo o que aparece no painel e na planilha sai de uma única consulta à API de dados abertos do Compras.gov.br. Nada é digitado à mão.

De onde vêm

API pública do Compras.gov.br (SEGES/MGI), sem chave e sem cadastro, retorno em JSON:

https://dadosabertos.compras.gov.br/modulo-contratos/1.2_consultarContratos_FimVigencia

A consulta é feita pelo órgão SIAFI 26235 (UFG), que é a mesma base alimentada pela própria UFG no Compras.gov.br.

O que entra na base

O filtro é a data de fim de vigência: de hoje até hoje mais 730 dias. Ou seja, contratos que vencem nos próximos 24 meses. Daí decorre que:

  • contrato já vencido não aparece;
  • contrato que vence depois dos 24 meses entra sozinho na base conforme a janela avança;
  • contrato prorrogado, com aditivo já registrado no sistema, aparece com a data nova na coleta seguinte;
  • registro marcado como excluído na origem é descartado.

Não existe nenhum outro filtro. Nada é cortado por valor, modalidade, contratada ou objeto.

Como a coleta roda

O atualizar.py chama a API, pagina de 500 em 500 registros até acabar (hoje são duas páginas) e regrava o dados.json com a data da posição. Se a API estiver instável, cada página é tentada quatro vezes; se ainda assim não vier, a execução aborta sem gravar, para não publicar base pela metade.

Roda sozinho às 6h da manhã, em dias úteis, pelo GitHub Actions, e pode ser disparado na mão pela aba Actions. Cada atualização vira um commit datado, então dá para recuperar a base de qualquer dia passado e mostrar como um contrato estava numa data específica.

O que é calculado aqui, e não vem da API

  • Dias restantes: diferença em dias corridos entre o fim da vigência e a data da coleta.
  • Situação: crítico até 180 dias, atenção de 181 a 365, regular acima de 365. Faixa que definimos aqui, a API não devolve esse campo.
  • Fundação de apoio: marcado quando a razão social contém "FUNDACAO". É identificação por nome, então uma empresa qualquer que tenha "fundação" na razão social seria marcada indevidamente.
  • Deduplicação: guarda um registro por contrato mais UG de origem, porque a API repete o mesmo contrato quando há mais de um evento de vigência.
  • Corte de texto: objeto em 160 caracteres e razão social em 60, só para caber na tela. O texto inteiro continua na fonte.

Conferir por conta própria

Cola no navegador, ajustando as datas, e vem o JSON bruto do jeito que o script recebe:

https://dadosabertos.compras.gov.br/modulo-contratos/1.2_consultarContratos_FimVigencia?pagina=1&tamanhoPagina=500&codigoOrgao=26235&dataVigenciaFinalMin=2026-08-18&dataVigenciaFinalMax=2028-08-17

Para auditar uma linha da planilha, procura o número do contrato no JSON e compara data de fim, valor e fornecedor. Divergência só acontece se a posição da coleta for anterior a algum registro feito depois no Compras.gov.br.

Para refazer a coleta inteira, basta Python 3, sem biblioteca externa:

python3 atualizar.py

Limitações

O valor global é o valor total contratado, então não dá para usar a planilha para ver saldo ou quanto já foi executado.

Aditivo que ainda está tramitando não aparece na API, então pode ter contrato marcado como crítico que já está com a prorrogação encaminhada. Quem sabe disso é o gestor do contrato.

Contrato formalizado fora do Compras.gov.br não entra. Gestor e fiscal também não vêm, esse serviço da API não devolve esses campos.

Se o lançamento está errado no Compras.gov.br, ele chega errado aqui, porque o script não corrige nada. Quando a planilha divergir do que a unidade sabe, o acerto é na origem.

A base é sempre do dia da coleta. Vale citar a data que está no topo do painel quando a planilha for para algum documento.
